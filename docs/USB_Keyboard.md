# The C64 keyboard as a USB keyboard

A special firmware build, "TeensyROM + USB keyboard", lets the C64 or C128 keyboard type
into whatever the TeensyROM's micro-USB port is plugged into: a PC, a Mac, a MiSTer.
[PETSKEY Remote](https://github.com/wesbiggs/petskey-remote) runs on the C64 and sends each
key press and release through the SwiftLink; the firmware turns them into a standard USB
keyboard. No Ethernet, no host software, no driver on the other side.

This is not in the release images. Build it with:

```
node tools/build-firmware.mjs --target tr-plus --usb-keyboard      # or --target tr
```

It writes `TeensyROM+_<ver>_usbkbd_full.hex`.

## Using it

1. Flash the `_usbkbd` image and plug the TeensyROM's micro-USB port into the computer.
2. On the C64, start PETSKEY REMOTE with the SwiftLink handler (Swift-Turbo/Modem) and set:
   - Host: `USB` (the port is ignored)
   - Modem init command: empty. The default `atc` starts Ethernet before every dial,
     which waits for DHCP and fails with no cable.
3. The status line says "Linked to USB keyboard.", or "(no USB host)" when nothing has
   set up the USB side.

**RUN/STOP + RESTORE** hangs up as usual; every key held on the USB side is released.
If the C64 is reset with a key down, the key is released after 3 seconds without a byte.

## What it is

- **USB device:** the stock Serial + MIDI interfaces plus a boot-protocol keyboard, product
  ID 16C0:048D instead of 16C0:0489. The serial port may get a new COM number on Windows.
  The ID is provisional: PJRC has not allocated it.
- **Firmware:** `ATDT USB` (or `ATDT USB:<anything>`) connects to a built-in endpoint
  instead of TCP (`AT_DT`). While connected, each byte the C64 sends goes to
  `IO_Handlers/UsbKbd.c` instead of the TCP stack; `+++`, a reset, or leaving the handler
  ends it. Without `--usb-keyboard` none of this is compiled.
- **Keymap:** the one PETSKEY sends (protocol 2). It holds Linux key codes;
  `UsbKbdKeys.h` maps them to HID usages, generated by petskey-remote's
  `tools/hid_keytable.py`. PETSKEY protocol 1, which sends no keymap, is told to update.

## Differences from the network host

- HID sends key positions, so the computer's keyboard layout setting matters. The default
  keymap assumes a US layout.
- Six keys at once plus modifiers (boot protocol). The C64 keyboard ghosts on three anyway.
- Keys with no HID usage up to 0x7F type nothing: LINEFEED, MENU, PRINT, the media keys,
  and RO (the positional layout's `=`).
- Keys pressed before the keymap arrives are ignored (PETSKEY sends it right after the hello).

## Not yet tested on hardware

Host build only. Still to check on a board: enumeration on Windows, macOS and Linux with
`trserial`, the TeensyROM UI and `npm run flash` finding the new ID; bus timing (cartridge
games with the device port plugged in, then fast typing in PETSKEY); every key against
`netkbd_host.py --dry-run`; and a MiSTer.
